# 交互数据表规格

状态：沿[成熟度路线](<../proposals/2026-10-18-uilib-maturity-roadmap.md>)推进数据视图；本专题复用[交互集合](<2026-10-18-uilib-virtual-collection-spec.md>)和[命令](<2026-10-18-uilib-command-spec.md>)合同。

前端案例采用TanStack React的[可编辑数据表](<https://tanstack.com/table/latest/docs/framework/react/examples/editable-data>)和[可变行高虚拟表](<https://tanstack.com/table/latest/docs/framework/react/examples/virtualized-rows>)。具体行为对照官方v8的[编辑示例源码](<https://github.com/TanStack/table/blob/v8/examples/react/editable-data/src/main.tsx>)与[虚拟行示例源码](<https://github.com/TanStack/table/blob/v8/examples/react/virtualized-rows/src/main.tsx>)：输入框保留普通编辑与Tab入口，案例在失焦时把草稿写回数据；表头与单元格共用列宽，表头固定，有限行用实际测量校正高度。数据表延续普通表格子控件模型，不附加ARIA grid式单元格方向编辑模式。

## 1. 用途与职责

页面提供业务行、稳定行键、有序列声明和单元格内容，Core呈现对齐表头、可变行高和有限行视图。列头可以是普通标题、共享排序命令或正式组合控件，单元格可以含按钮、图标、只读内容和独立编辑草稿。排序、过滤、选择及文件写入仍由业务状态决定；数据表不另存一份业务表、不隐式更改行顺序或选择。

表头固定在纵向正文之前；正文纵向滚动时表头保持可见。所有列共用同一横向位置，表头和当前行始终对齐。宽度不足时允许横向滚动，不压扁列的已声明最小宽度。表格嵌入其他布局时仍沿父约束、原SceneScrollArea及共同裁剪/显露，不让页面同步表头和正文的像素位置。表格外框把正文纵向滚动条放在可见正文右边，绑定原行集合的纵向端口并显式替代其默认条；它不随全宽列内容横移，底部与横向条交角让开。

## 2. 稳定行与列声明

公开SceneDataTable以数据来源、行键函数及列来源创建。行视图使用原SceneVirtualList；公开node、行集合和横向端口，调用方仍可按稳定行键请求显露/焦点并组合现有滚动条。独立草稿或选择可以跨离屏保留，真实删除按集合生命周期结束。

每列有非空稳定业务键、可追踪宽度意图、表头工厂和单元格工厂。列来源顺序就是表头、单元格和Tab声明顺序；发布新的列表可隐藏、恢复或重排列。活跃列键重复时使用可定位错误通道，不按最后一项覆盖。列键与行键、实际单元格节点及其挂载代际分别表达逻辑身份、视图和输入联系。

同一列对象中的宽度来源可以动态变化，不重建单元格；仅重排列位置时保留原列对应的当前节点。以同列键发布新列声明时，结束该列旧呈现工厂的产物，按新声明创建表头与当前行单元格，避免旧动作闭包继续使用旧定义。结束呈现不清除业务独立草稿。行或列退出期间的旧输入联系不会激活后来占据同位置的新对象。

## 3. 共享列宽与有限测量

列宽接受既有Size.fixed或Size.fill及其min/max边界，含义与普通布局相同。数据表为每一行和表头提供相同总宽度、列间距及列宽意图，复用原流式布局的有界权重分配，不能按每行内容另算自然列宽。Size.natural在这个新入口不表达全表自动宽度，传入时给出明确错误；普通布局的自然尺寸用法保持原条件。

全表最小宽度由当前列的固定宽度或填充最小值及间距决定。列数/列宽/窗口/字体变化后，表头和有限准备行同步使用当前声明和资源。单元格可以自然高、换行和嵌套编辑；每行高度由已准备单元格正式测量，行间使用原可变高度索引及滚动锚定。列宽分配条件、列显隐及列定义更换作为行高度的度量条件，使原集合结束依赖旧列条件的高度事实并按原锚定重测有限行；总表宽不变也不能复用旧换行高度。该条件只扩展表格内部的原高度失效接点，不改变既有SceneVirtualList.create的入口或使用前提。空列时投影为空行视图来源，恢复列后按当前业务行准备。未创建的行不为求全表最大字宽而调用工厂、排版或读取字体资料。

始终存在的列盒承载列宽及位置，工厂产物放在盒内；某单元格内容visible=false不使后续列左移。表头及单元格内容自身的padding位于已分配列盒内，不能因为标题或正文内容不同造成列起点漂移。横向及纵向位置、滚动条、命中和必要显露均来自同代正式几何；列内容很宽时纵向条仍在可见外框边缘，横向与纵向各保留一个原位置所有者。运行中改列宽无需业务读回窗口宽度或调用layout。

中性语义按[React Aria Table的表头、行与单元格关系](<https://react-aria.adobe.com/Table.md>)表达当前真实视图。TABLE的count是纯数据行总数；rowCount包含一行表头，表头row为1，数据行从2开始，column从1开始。ROW、COLUMN_HEADER和CELL使用同一逻辑坐标与总数，单元格以labelledBy关联当前完整表头名称；未挂载行不生成语义节点。

## 4. 列操作、输入与状态

排序入口使用共享SceneCommand，表头动作即时读取可执行条件；动作更新业务的排序来源或Computed行投影。表格只呈现随后发布的行顺序和排序标记，不自动猜比较器、升降方向或空值顺序。隐藏、显示、宽度与重排通过相应列来源声明表达，后续列拖动交互可以消费同一来源，不要求为现有调用方新增原生监听。

每个单元格保留正式控件的焦点、点击、文本、组字及ESC语义。Tab依行/列/单元格内部的逻辑声明顺序跨越屏外行；输入字段先处理光标、选区和Home/End，只有未被控件消费的四方向才按当前几何和相邻逻辑行准备。案例备注沿正式字段BLUR请求接受草稿并写回业务来源，不只显示保存反馈；数据表不另设提交策略。只读字段仍可聚焦查看，禁用单元格按原资格跳过。选中行不代表聚焦某个单元格；复选列可以使用SceneSelection，不由滚动或排序隐式修改选择。

排序或列变化与后续输入位于同批时，先结算前一动作与当前声明，再把后续输入交给仍有效的实际目标。行键仍存在时不把草稿改绑给新行；列被真实隐藏/替换时结束旧挂载及组字/按压联系，不能将旧尾部交给邻列。

## 5. 生命周期与验收

表格使用原Signal/Computed/Owner、NodeBinding、虚拟集合、正式子测量和滚动端口，不建立单元格输入树、焦点系统或独立偏移权威。当前行数增大时，表头与逻辑元数据成本单列，昂贵单元格树/度量仍围绕实际准备范围。卸载、重挂和关闭释放所属观察及旧呈现，业务数据来源仍归调用方。

真实消费使用可排序的任务/资源表，包含标题、状态、可修改字段和独立动作。用法示例直接构造列和业务投影，不依赖测试专用接缝或节点下标定位内容。

| 场景 | 可观察结果 |
| --- | --- |
| 千行混合内容、首次进入与滚动 | 表头固定，单元格树有界，可变行高和正文滚动正确 |
| 窗口变窄、列宽变化与横向移动 | 列最小宽度保持，表头和每行同列边缘一致，无人工位置同步 |
| 排序、过滤和单元格编辑 | 业务投影生效，稳定行键保留独立草稿，动作条件与按钮一致 |
| 字段方向/Home与Tab失焦 | 光标操作不切单元格，Tab到下一控件后仅一次接受草稿并写回业务值 |
| 动态隐藏、重排及替换列定义 | 挂载身份按合同保留或结束，旧尾部不激活新列，焦点资格同步 |
| Tab及方向跨屏、同批随后文字 | 先准备实际单元格，文字进入新草稿，必要显露沿原端口 |
| 空行集、空列集及无目标行 | 没有虚假焦点或永久准备例外，业务状态不被擅自清除 |
| 数据/列异常及卸载 | 明确定位重复键/非法尺寸，所属已取得资源按原失败通道清理 |

稳定逻辑通过正式ScenePageSession验证，实际列对齐、可读性和输入回调通过宿主可见画面核对。
