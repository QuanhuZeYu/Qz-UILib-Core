# 场景检查与真实配置工作区

[成熟度路线](<../proposals/2026-10-18-uilib-maturity-roadmap.md>)最后阶段为页面作者提供同一场景的检查入口，并在实际配置工作区使用已建立的控件与交互。作者应能回答：节点分配在哪里、当前为何被裁掉、谁持有焦点或指针，以及哪项真实变化要求重新准备。检查读取现有权威，业务动作仍走原Scene和Session。

采用[React Developer Tools](https://react.dev/learn/react-developer-tools)及[对应完整正文](https://raw.githubusercontent.com/reactjs/react.dev/main/src/content/learn/react-developer-tools.md)中检查组件、定位状态与性能问题的用途；采用[MDN调试CSS](https://developer.mozilla.org/en-US/docs/Learn_web_development/Core/Styling_basics/Debugging_CSS)及[对应完整正文](https://raw.githubusercontent.com/mdn/content/main/files/en-us/learn_web_development/core/styling_basics/debugging_css/index.md)中选中对象、查看盒模型和有效属性来源的交互。实现继续UILib原场景、挂载身份、共同几何、输入路由和失效入口；不引入浏览器工具或另一套布局系统。

## 1. 按请求读取当前事实

正式Session提供一次检查请求，沿当前页面域和原准备入口处理，返回不可变纯值快照。它在请求之前的已递交工作完成准备后读取当前一致事实；结果携带页面/呈现代次、几何与资源版本，不能把不同批次的焦点、节点与布局拼接成一个当前状态。

快照包含当前实际挂载的有限节点层级、原节点身份与本次挂载身份。结束后重挂的对象不会沿用旧挂载联系；所属层、默认滚动条和普通孩子使用原真实归属。未实例化的虚拟行保留所属控件的逻辑计数和当前有限视图事实，不为检查构造屏外节点。

每项提供原布局盒、当前world包络、变换、精确有效裁剪和实际可见区域、滚动偏移/范围，以及有效字号/内距/间距和作者或控件默认来源。自定义控件类型使用实际类型信息，名称和语义角色可沿当前已声明语义关联。几何纯值与[矢量呈现](<2026-10-18-uilib-vector-presentation-spec.md>)同源，裁剪孔不能退化成包围矩形；[尺寸密度](<2026-10-18-uilib-density-spec.md>)明确覆盖和主题默认不能只显示最后数字而丢来源。

快照同时给出原有效范围、当前焦点、悬停、按压/捕获的实际目标及物理按键占用。捕获是否存在与按压颜色分别消费原Router状态，不根据控件类型猜测。已关闭Session返回明确的结束状态与空当前树，等待中的请求沿原关闭/失败语义完成。导出值不含SceneNode、Signal、Runtime、原MountHandle或可执行动作闭包。

## 2. 失效与工作量说明

失效记录显式启用，默认关闭。启用后在现有失效入口汇总本批来源与类别：声明绑定、自然测量、排列/范围、绘制、资源/视口与输入产生的相关准备。能确定节点时关联其原挂载身份；全局原因明确属于页面或资源，不伪造节点来源或因果堆栈。

记录只保留最近已完成的一批及尚待准备的合并原因，同一节点/类别的重复通知合并。工作量来自实际执行点的测量、排列与绘制收集计数，说明真实做过什么，不把revision增长当成执行次数。未启用时不遍历场景生成日志，也不保留变更历史；关闭记录或结束Session释放其持有的观察和节点索引。

检查请求本身不修改业务数据、焦点、滚动、显露意图、组字或指针联系。它可触发原已失效工作的必要准备；稳定事实复用原结果，不以读取强制重测或重绘。开启记录对原错误传播和所属资源清理不增加静默回退。

## 3. 可使用的检查页面

共享检查页以一个真实可编辑、可滚动、可变换和裁剪的场景作为被检查对象。作者可以选择对象，查看布局/呈现盒、有效裁剪、焦点/捕获与最近准备原因，并手动更新。控件名称、数值和单位可读，节点不存在或已重挂时显示当前状态，旧选择不转投后来对象。

对象定位和可选高亮使用同批world几何，检查面板自己的读取不建立第二输入路由，也不通过模拟事件改变被检查控件。默认手动更新避免面板观察自身变化形成连续失效。检查仍可作为Session公共入口被真实开发工具读取，页面只是普通消费者。

## 4. 正式配置工作区的实际消费

优先打磨已由Minecraft UILibGuiFactory装配、接真实SettingsConfiguration的SettingsPage。配置文件、字体事实、保存/重载和离开确认继续原唯一权威；主题、布局、字段、按钮、菜单和快捷键使用正式控件与同域状态。

在实际工作区接通一致名称/描述、可执行状态和共同动作，展示当前字号/密度或检查入口时沿所属正式声明消费。草稿和接受/拒绝仍沿原SceneEditState，不因主题或检查重建。重复的基础组合回到所属控件合同；服务特有业务裁决留在SettingsConfiguration/Model，宿主继续只装配原生命周期。

跨仓只使用明确版本和Java目标的Maven产物。本阶段不把已在旧依赖上的独立业务仓自动改成另一套入口，不添加跨仓源码依赖；真实配置工作区的交付包括实际正式消费和可操作结果。

## 5. 验收

| 场景 | 可观察结果 |
| --- | --- |
| 当前字段、层和有限集合读取 | 同批层级、挂载身份、布局/精确clip与语义事实一致，屏外行没有为检查而构造 |
| 原字段聚焦、拖动捕获、模态范围与关闭 | 检查准确反映原Router事实；读取保持草稿、选区、焦点、组字和物理占用 |
| 作者padding0/完整字号、主题默认与动态密度 | 有效值和来源可区分，检查不改写声明 |
| 文案、配色、尺寸、视口和资源变化 | 记录对应真实来源与准备类别，实际执行计数能区分只绘制与重测 |
| 静止请求、停用记录、重挂与结束 | 稳定工作复用，旧挂载不复活，等待请求结束，无持续日志或历史节点保留 |
| 实际配置页编辑、保存/拒绝、字体刷新及返回 | 同一正式依赖链可读可操作，状态与资源沿原服务生效，检查与主题更新不提交业务草稿 |

稳定逻辑通过正式ScenePageSession和真实配置服务取证。宿主可见画面、系统输入、GPU与设备生命周期沿原对应入口验收；用户桌面占用期间先完成无窗口实现、软件像素反馈及正式成品消费。
