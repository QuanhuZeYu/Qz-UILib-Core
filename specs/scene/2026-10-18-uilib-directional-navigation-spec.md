# 方向焦点导航规格

状态：沿已认可的[成熟度路线](<../proposals/2026-10-18-uilib-maturity-roadmap.md>)授权设计和实施；行为验收独立于命令快捷键阶段。

## 1. 方向意图与唯一焦点

页面的四方向导航表达向左、右、上、下寻找下一个交互目标。键盘未消费箭头与宿主提供的中性方向意图共用规则；设备键码、手柄轴、阈值及物理重复来源归宿主，Core不枚举设备、不读取原生队列。方向意图不激活业务、不修改选择，也不隐含提交字段；正常焦点离开的已声明BLUR仍沿编辑合同。

方向输入及空间导航的箭头repeat每次先交唯一当前编辑目标和既有editActivator消费。文本的光标、选区、滚动查看，以及拖动/排序等复合控件的已声明方向操作保持优先；已消费即停止，即使没有可见变化。IME保留同一事件，不能同时移动焦点。标准键盘解释只在无Primary/Alt/额外修饰键且编辑未消费时进入方向焦点导航，宿主原有Ctrl方向等编辑用法保持。直接中性方向事件也沿原事件队列，完成编辑与Effect后才进入后续导航；原范围已经改变时结束该事件，不转投新模态或返回外层。

方向导航与Tab/Shift+Tab分别表达空间方向与逻辑声明顺序。Tab保留当前范围循环及初始/返回策略；四方向不循环，所选方向没有合法目标时保持当前焦点。没有焦点时沿当前范围的默认逻辑首目标建立焦点，不执行初始/恢复声明策略。最终选中、显示键盘焦点线索及最小必要显露都由原SceneFocusRouter负责，不建立另一个方向焦点。

## 2. 同批几何中的目标比较

候选来自当前有效输入范围内的可聚焦节点，沿原隐藏、禁用、只读、所属层和挂载代际规则核验。位置使用本事件已结算的SceneGeometryView；不缓存跨窗口/字号/资源变化的静态邻接表，不以节点UUID、绘制层高低或创建时间决定相邻目标。滚动正文中的屏外目标继续可达，裁剪本身不删除逻辑内容。

以原目标及候选的正式矩形比较。候选中心必须严格位于请求方向的半平面，当前目标不作为自身候选。距离采用Norigin corners评分：正交投影交集达到原目标该轴长度的20%时视为相邻；主轴距离为原目标请求侧边与候选相对侧边的像素距离，正交距离取两端点之间最短像素距离。相邻得分为(5×主轴距离+正交距离+1)/5，斜向得分为5×正交距离+主轴距离+1，取较小者。相邻是有限偏好，不因一点投影交集越过明显更近的合法斜向目标。得分相同沿当前逻辑声明顺序选首项；统一放大5倍用足够宽的整数精确比较，坐标和中心和也使用宽整数。

例如，向下时在相近距离优先同列，向右时在相近距离优先同行；远处同列目标不能压过紧邻斜向目标。方向不靠数组下标猜二维关系。布局、尺寸和顺序变化后使用当次事实重新比较。目标有几何但尚未显露时，最终选择后沿原滚动位置所有者和共同显露合同推进，页面不读回位置补偿。

## 3. 复合边界与按需内容

普通已实例化内容由共同几何选择。按需复合控件沿现有有限导航准备协议提供方向候选；目标准备、真实测量、最终资格核验及取消仍属于同一次导航。原逻辑遍历接口和只实现顺序导航的旧扩展继续可用。复合行中的逻辑后续使用同一子树遍历准备：SceneRuntime.beginFocusTraversal返回由本次导航拥有、边界不循环的游标；外层不得只遍历当前已创建的内层行而提前判空。

从复合内容内部开始时，先让该复合内容在所选方向寻找候选。纵向虚拟集合在同一行内按真实几何选择；向上/下越过行内边缘时，按完整当前逻辑顺序准备前/后一行，并在该行选取与原目标横向位置最接近的合法目标。无目标的行继续本次有限搜索，实际目标键退出时取消本意图，不转投占据相同位置的后来对象。向左/右不隐含换行或末尾循环。集合边界已经耗尽时，再由同范围外部几何选择，衔接前后或侧边控件；不能因为后续逻辑行未实例化就直接跳出集合。

从集合外进入时，将复合边界按其正式区域参与外部候选比较，再在当前呈现范围内以同一方向及原位置选择实际交互目标；必要时按其逻辑入口有限准备，不预先构造全列表。复合边界无合法实际目标并返回END时，关闭该边界游标，从剩余外部候选继续同方向比较；空集合或全无目标的边界不能截断下方页脚等合法目标。CANCELLED表示原联系失效，结束整个本次意图，不转投剩余候选。嵌套复合边界由最近实际所属边界开始，耗尽再向外层推进，不由多个协作者同时拥有导航状态。

待准备期间继续复用唯一焦点及原范围记录；有效旧焦点保持，不产生虚假失焦提交。准备完成后再由路由核验当前范围、原起点联系和目标挂载，必要显露后才处理同批下一输入。隐藏、禁用、真实删除、范围结束、新的显式焦点请求或新导航会终止失效准备；关闭释放游标与所属呈现意图。行工厂和昂贵测量围绕本次候选及有限准备范围工作，逻辑元数据仍可随条目数增长。

## 4. 使用与验收

标准场景提供实际二维按钮/物品布局，保留每个按钮的真实动作，并支持尺寸变化、方向操作和滚动。键盘箭头、正式session中性方向事件与焦点线索使用同一结果；无需业务声明左右上下的静态节点表。按需列表场景保留每行多个动作、可变高度和独立编辑状态。

| 场景 | 可观察结果 |
| --- | --- |
| 二维布局向四方向移动、边缘及等距 | 选择同列/同行合理目标，按当前逻辑顺序解平局，边缘保持焦点、不激活动作 |
| 宽度/字号变化、重排及禁用隐藏 | 使用当前几何与资格；Tab仍按逻辑声明顺序循环 |
| 文本光标、只读字段、IME及复合拖动 | 原方向语义先消费，不重复转移焦点或执行业务 |
| 目标在普通或嵌套滚动正文内 | 最小必要显露，画面与后续命中同代 |
| 虚拟行内左右、跨屏上下及集合边缘 | 同行几何正确，相邻逻辑行按需到达，末端再衔接外部目标 |
| 准备中目标删除或范围切换 | 旧意图结束，迟到输入不落到邻行或后台 |
| 方向后同批编辑文字 | 后续输入进入最终新焦点，准备不延迟到下一帧 |
| 旧逻辑导航和主动焦点请求 | 原入口、循环、初始/返回不显露及声明用法保持 |

稳定规则用可复算几何和正式ScenePageSession验证；实际排版、方向线索与命中通过真实桌面画面和原回调核对。手柄硬件与具体游戏设备桥只报告实际验证组合，不从中性方向事件模拟推断设备实测。

## 5. 前端参考与采用行为

[Norigin空间导航实际React示例](https://github.com/NoriginMedia/Norigin-Spatial-Navigation/blob/master/apps/react-demo/src/App.tsx)组合横向卡片、纵向内容和本地箭头消费；[距离说明](https://raw.githubusercontent.com/NoriginMedia/Norigin-Spatial-Navigation/main/docs/guides/distance-calculation.md)及[当前排序实现](https://raw.githubusercontent.com/NoriginMedia/Norigin-Spatial-Navigation/main/packages/core/src/SpatialNavigation.ts)为有限相邻偏好的依据。上述公式对应实现的相邻主副距离交换和5倍权重，不使用说明页的简化式替代。Core保留自己的当批SceneGeometry、原半平面资格和稳定逻辑平局，不移植DOM坐标或另建焦点。

[React Aria FocusScope/useFocusManager](https://react-aria.adobe.com/FocusScope.md)提供范围约束、焦点返回及逻辑顺序移动参考；[useKeyboard](https://react-aria.adobe.com/useKeyboard.md)的字段示例先由当前目标处理方向。空间repeat进入文字字段后仍消费当前字段光标/选区；Tab维持其独立逻辑遍历合同。
